# 首版架构与决定

2026-11-09。MyEval 是独立执行和证据层，Langfuse 是可替换的观测投影；SQLite 与开放 JSON/JSONL 是本机证据来源。

## 执行与身份

任务包声明案例、输入、初始状态、来源截止、虚构标记、期望行为、量表和两个配置。建立实验时冻结完整任务包、选中案例、请求配置、产品代码/dirty/提示词/适配器哈希。worker 在调用产品前比较当前来源与冻结值；排队/重试期间源码变化会成为显式失败，不能暗换版本。

独立案例是采样单位；同一案例×配置×repeat 形成 trial。trial 的执行重试形成 attempt，保留旧终态、输出与事件，不增加独立样本数。产品内部模型重试另由 stage/attempt 关联，不能与整次执行重试混同。默认最多 2 个并发、每实验最多 60 trial、重复最多 5 次、执行尝试最多 3 次、单 trial 5–900 秒。用户建设预算不限不代表无限模型请求。

每次执行使用独立 worker 进程、工作目录、产品端口/SQLite/轨迹。runner 发送协作停止标记，8 秒后才中断进程，11 秒后可强制回收；worker 意外退出仍回收它的产品进程组。思间 bridge 单独回收 Codex CLI 的进程组。供应商计算和计费没有独立确认接口，保持 unknown。

SQLite 在首次调度前记录所有 trial。每次尝试的 request/result/events 文件独立保留。服务重启先核对并清理属于该 trial 的遗留进程；已有完整 result.json 则恢复终态，没有终态的在途或排队 trial 标 interrupted，均不自动重放。文件原始结果与数据库恢复分别记录。平台回执按 trial+attempt 回写，避免旧尝试的异步回执污染新尝试。

## 共享业务边界

- Sijian：启动原产品 `services/agent/server.py`，调用真实发现/复盘校验、提示词和 CLI；最小产品改动只有 `--trace-root` 和退出回收。V13/历史评测参考字节不变。
- pome：同一产品 Handler/Store/API，增加可选的内存 runtime_settings、白名单 observation sink 与候选/审校 effort 覆盖；正常入口不装 sink，原有默认 low、提示词、声音及用户资料不变。每个配置的后续轮次使用自身实际交付 final，候选只作轨迹，不进儿童上下文。完成后通过真实状态 API 保存并复读。
- 新项目增加 `myeval/adapters/<project>.py` 与任务包；公共 runner、实验、盲评及导出不写项目质量规则。

## 证据与评价

可观察事件携带 UTC 时间和 episode/turn/stage/attempt；保存公开输入、模型正文、用量、工具/状态事实，不保存隐藏思维链。请求值、生效值、unknown 分开；无价格版本的费用为 null。规则检查只核验声明的边界，不自动证明语义价值。

人工评价、验收试填、外部模型评价分开存储。匿名展示带有不暴露映射的 revision，保存评价时在同一存储锁/事务内核对两侧 attempt 与结果 hash；过期页提交返回 409，不能自动套用到重试后的输出。评价归档保留两侧结果身份，匿名投影不返回它们。模型评价也关联具体执行尝试和结果哈希；产品审校不是评价器。比较保留全部 trial 分母和所有执行尝试状态，人工分歧不覆盖，无综合高分。

管理员 API 需要本机随机 capability，凭据文件 600，浏览器只在当前管理员标签 sessionStorage 保留。匿名 API 采用字段白名单，未评价时不返回 trial/config/hash/trace 映射；评审左右随机映射持久化，保存后才能主动揭示该配对。匿名页没有管理员 API 凭据，也不预取管理数据。该机制用于本机评审偏差控制，不保护数据免受有源码/文件权限的管理员读取。

管理员导出含全部案例/配置/尝试/阶段/评价和可移植附件哈希。附件只读 trial 内的声明路径和固定可见证据文件，拒绝路径逃逸、符号链接和凭据/SQLite批量打包；pome payload 已由产品观测白名单过滤。匿名导出保持同一匿名投影。

## 平台选择

遵循优先验证 Langfuse 的既定方向。本机首次没有容器运行时，安装官方 Colima/Docker 后，独立 8 GiB VM 已实测部署、入库、读回和停机恢复；无需同时安装 Opik。实际当前版本为 v4，因此使用官方 OTLP/HTTP，不使用已弃用的旧 ingestion。此决定以部署和两项目真实接入证据为依据，见 [平台记录](platform.md)。

平台 session 关联 MyEval experiment，平台 experiment 按 configuration/repeat/attempt 拆分，case ID 作为稳定 item；防止平台把重复采样合并。先落本地，再有界发布。明确接收回执防重复；接收结果未知只读回，不能盲重发。平台同步失败不更改业务执行状态。MyEval 无独立 SaaS、企业角色、收费订阅或生产备份承诺。
