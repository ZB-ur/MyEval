# MyEval V2 的工作原理与适用范围

本文描述 V2 的实现与适用范围。2026-11-25 集成版本包含当前界面与独立演示；见[发布验收](acceptance/2026-11-25-release.md)。三项目业务结论仍来自 [2026-11-18 历史验收](acceptance/2026-11-18-platform-v2.md)，本次打包不新增模型质量结论。

## 一次比较的证据链

```mermaid
flowchart LR
    D[版本化材料与来源] --> F[冻结案例、配置与源码]
    F --> T[真实产品入口执行]
    T --> A[逐次尝试与可观察证据]
    A --> J[独立 AI 评分与匿名评阅]
    J --> C[按家族比较与覆盖说明]
    C --> G[有条件的质量判定]
    A --> E[导出、归档与恢复]
    J --> E
```

系统首先固定“比较什么”：材料版本、案例家族、基线与候选、执行参数和来源哈希。每个案例 × 配置 × 重复序号形成 trial；失败后的重试产生新的 attempt，旧输出与失败不删除，样本数不增加。工作进程在发送产品请求前再次核验来源，防止排队期间修改提示词后仍声称是同一个实验。

适配器调用产品共享的业务入口。pome 使用真实 Handler/聊天/整理/状态保存，Sijian 使用真实发现与复盘服务，Sidelit 使用产品共享 Swift/C++ 视觉模型 runtime。公共执行层只管理身份、隔离、生命周期和证据，不写项目质量判断。

评价发生在交付之后：评分作业冻结具体 attempt、结果哈希、匿名投影、量表、评分器和原图。评分模型没有执行工具权限，只保存公开判断、引文和用量。引文校验能证明引用存在，不能证明语义判断正确。规则、独立 AI、真人评价和验收试填分别保存；产品内部审校不算独立裁判。

比较先归并同案例的重复，再按情境家族等权。配对必须来自同一案例、重复和完整双侧输出身份；不把两名裁判、两次重复或同图两个意图算成更多独立图片。区间、有效家族、缺失配对、失败及分歧共同呈现。没有真实人工标签时，AI 校准只能说明与内部规范锚点的一致性。

质量判定是一份有证据身份的检查记录。它可以通过、失败或证据不足；执行成功但缺少质量条件不能通过。后续评价或尝试改变后，旧判定保留并标明证据已更新。批次只组织实验，不把不同项目平均为一个分数。

## 已走通与尚未覆盖的典型场景

| 场景 | 本轮支持与证据 | 适用边界 |
| --- | --- | --- |
| 提示词、模型参数、多候选离线比较 | 2–16 配置、不可变材料、重复/attempt、独立评分与历史重评；三项目真实执行 | 小规模本机调度；不是分布式训练或大规模评测集群 |
| 长输出与证据审阅 | 原文、图片、逐项引文、匿名席位、分歧、导出 | UI 独立盲审仍按各轮报告验收；不是教师或用户满意度调查 |
| 动态多轮对话 | 脚本、规则分支、模型模拟用户；pome 已真实交替调用并整理保存 | 模拟用户仍可能补造事实；没有证明与真实儿童行为分布一致 |
| 图片理解与意图建议 | 公开许可图片、字节哈希、实际图片送评；Sidelit Mac 原生推理 | 未证明 iPhone 推理、物理相机、快门、热状态或能耗 |
| 跨 episode 状态和最终产物 | 隔离文件 workspace、快照/reset、再次打开读回、文件产物核验 | 是文件级组件验收；未普遍接管产品数据库、浏览器与外部服务状态 |
| 原生和语音产品旅程 | Sijian Simulator 文字复盘/引用/保存/重启；pome 合成语音真实 ASR/chat/音频回复/保存；Sidelit Simulator Vision 回放 | 真实操作记录，尚非通用无人值守 GUI/音频评测器；无真人听感、真实儿童或真机结论 |
| 历史轨迹回流与再评价 | 导入既有终态和媒体，保留来源/失败，指定历史 attempt 重新评分 | 不重放生产写入；不是已接入生产流量的在线 A/B 或灰度发布 |
| 恢复、审计与可搬运证据 | SQLite、JSON/JSONL、不可变收据、媒体归档、ZIP、校验备份与独立目录恢复 | 本机管理员能力码；没有企业 RBAC/SSO、多租户、远程灾备或生产 SLA |
| 有依据的优化选择 | 冻结开发/留出、完整失败记录、家族统计、质量与性能分开、候选淘汰门槛 | 没有自动搜索最优策略的承诺；统计不确定或未过门槛的候选不会因分数好看而晋级 |

还不能直接宣称完整支持：带真实工具副作用的通用多 Agent 环境、任意网站/原生 App 的自动闭环、RAG 检索金标与端到端引用评价、实时流式语音的延迟和听感质量、真实长周期用户效果、专家金标驱动的评分器有效性，以及团队规模的在线发布治理。现有适配器、任务包和证据边界提供扩展入口；这些场景仍需各自实际接入和验收。

## 本轮新增的测量修复

原评分器只接受文字子串，误拒绝空数组与数值证据。本轮增加独立版本的严格结构证据重验证：对整个原作业逐项处理，只有 JSON Pointer 定位到完全相同的类型和值时才接纳；原分数、理由和偏好不变，错误拼接引文仍失败。派生记录不构成新裁判或新样本，也不重复累计原模型用量。

每份收据保存全部原单位，包括无效和无响应。收据登记、有效评价导入、真实模型再次调用是三个不同动作，分别记录。原始失败、提供者额度中断和显式恢复尝试不会在最终结果中消失。详见 [评分契约](evaluation-v2.md) 与 [HTTP/CLI](api-v2.md)。

首版决策历史继续保存在 [architecture.md](architecture.md)，本轮不重写旧记录。

## 与主流能力边界的对照

2026-11-18 复核官方文档。这里对照的是已验收的本机能力，不能把外部产品文档计为 MyEval 已实现。

| 标杆方向 | 本轮已经补齐的部分 | 仍需单独建设与验收 |
| --- | --- | --- |
| Langfuse 的材料—实验—评价—回流闭环 | 版本化材料、多候选、独立评分、历史轨迹导入、匿名席位、证据导出 | 生产轨迹持续抽样、正式专家标注运营、团队分派与回流 SLA、CI 平台实际接线。官方提供生产轨迹入集、注释队列和 CI 实验集成：[说明](https://langfuse.com/resources/engineering/clarifications)。 |
| Inspect 的 Agent 与工具环境评测 | 真实产品适配、动态交互、状态快照与结果证据边界 | 通用容器/网络环境编排、工具副作用和多 Agent 世界状态；本机独立目录不等同完整沙箱。[官方沙箱说明](https://inspect.aisi.org.uk/sandboxing.html)。 |
| Promptfoo 的多配置回归与红队 | 多配置矩阵、预算、规则与独立 AI 分开、发布判定与 CLI | 自动攻击生成、系统性注入/泄漏/越权红队覆盖、实际 CI 阻断与线上灰度回滚。[官方红队入口](https://www.promptfoo.dev/docs/red-team/quickstart/)。 |

下一阶段应先补“评价是否代表真实用户”的证据：经授权的真实案例回流、教师/摄影师/思考写作者的分层专家标签、裁判与专家一致性及漂移监测。随后按具体产品需要接真机/实时音频/工具环境。不能通过增加模型裁判数量替代这些缺失，也不能承诺一次建设已经达到所有主流平台的终态。
