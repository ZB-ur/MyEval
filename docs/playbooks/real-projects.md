# 三个实际项目：从候选方案到采用判断

这份 playbook 展示 MyEval 已怎样用于思间 Sijian、pomegranagent-v2（日记本 pome）和 Sidelit。三个案例分别涉及文字思考助手、多轮对话与保存、图片理解；结论包含有条件的质量改善、仅有用量收益，以及主动淘汰候选。

**第一次使用，请先完成[图文操作指南](../walkthrough.md)。** 其中的办公案例无需业务项目、密钥或模型。下面使用同一工作台流程，但真实调用需要另行准备产品源码、兼容接口、模型环境和授权；clone 本仓库不能一键运行这三个产品。

本页配置 ID 与开发集数量来自仓库任务包；历史业务结论来自 2026-11-18 开始、11-19 封包的[公开验收记录](../acceptance/2026-11-18-platform-v2.md)和[结果交接](../handoff/2026-11-18-v2.md)。**公开开发任务包与历史正式留出集是不同材料。** 后者、真实运行原文、产品数据库及原始录像未随仓库发布；公开数字是历史汇总，不能仅靠本页独立重算，也不是本次文档更新重新执行的结果。

历史正式比较最终有 **313/320 个逻辑配对有效、7 个无效保留，真人评价为 0**。这不是 313 个独立案例，也不能由这一汇总推算各项目有效分母；详见[结果交接](../handoff/2026-11-18-v2.md)。

## 共用操作路线

```mermaid
flowchart LR
    Q[明确要改善的问题] --> D[开发集试跑和修订]
    D --> F[冻结基线、候选与来源]
    F --> H[独立留出材料正式执行]
    H --> R[原文、规则与独立评价]
    R --> J[质量与开销分别判断]
    J --> K[采用、保留基线或证据不足]
```

1. **准备环境。** 在启动服务的终端设置对应项目路径，准备已有授权的模型登录或本机配置。每个项目的前提见下文；缺少产品能力时先接入自己的 Agent，不把未运行写成通过。
2. **使用独立工作区。** 在仓库根目录运行 `scripts/run.sh --port 8331 --data-dir .local/project-playbook`，另开终端运行 `scripts/open --data-dir .local/project-playbook`。该目录保存自己的实验；产品也由适配器在独立端口和数据目录中运行。
3. **选择材料和方案。** 按下文任务包和配置建立实验，先用公开开发案例、重复 1 次。核对运行数、超时、并发与预算，再启动。看到 `source_changed_since_freeze` 时，根据新的来源另建实验，保留旧记录。
4. **阅读逐例交付。** 在“逐项运行”看状态和尝试，在“结果比较 → 逐例对照输出”对照同一案例，打开输入、原图、引用和阶段；先确认执行与数据边界，再判断内容。
5. **独立评价。** 具备评分环境时，在“模型评价”选择明确版本的评分器和本项目量表。可选 `codex-astra-v2`、`codex-sol-v2` 分别建立配对作业；二者分开报告。再邀请真人匿名评阅；只练习操作时选“验收试填”。
6. **记录决定并导出。** 读质量差异、家族数、缺失、重大问题及性能，再在“发布判定”保存条件和结论。导出证据供获授权者复核；管理员包含业务内容与方案映射，不直接当作公开匿名样例。

公开开发集可重复用于调试，但修订后要检验泛化，应按[冻结与判定协议](../experiment-protocol-v2.md)准备新的独立材料。看过的留出材料应转入开发/回归，不能改名后继续当作未见数据。

## 案例一：思间，精简回答能否保留有根据的思考推进

### 问题与比较设计

思间既要发现文字之间有意义的关系，也要围绕用户问题复盘。优化目标是减少重复、讲清依据与差异，同时避免把疑问升级为事实或凭空补充动机。更短、更长或联系更多，都不直接算更好。

| 项目 | 本案例设置 |
| --- | --- |
| 项目 / 公开任务包 | `sijian` / [`sijian-v2-development`](../../taskpacks/sijian-v2-development.json)，任务包版本 `1.1.0`。 |
| 公开开发材料 | 6 个虚构成人情境家族，3 个发现任务、3 个复盘任务；包括干扰材料、单侧条件、无联系、命名、历史边界与版本修订。 |
| 实验单位 | 一个固定发现或复盘请求是一个 case；3 方案 × 6 case × 1 次 = **18 trial**。同一请求的重试仍属于原 trial。 |
| 相同请求参数 | `mode=fixed_context_rerun`，`model=gpt-6-sol`，`effort=low`，`request_timeout_seconds=120`。实际生效模型/强度未获回执时保留未知。 |
| 质量量表 | [`sijian-v2`](../../rubrics/sijian-v2.json)：材料忠实、范围与来源、差异与不确定性、回应任务、思考推进、阅读负担。 |

| 角色 | 配置 ID | 产品 profile / 版本 | 检验的改变 |
| --- | --- | --- | --- |
| 基线 | `sijian-v2-baseline-v1` | `baseline-v1 / 1.0.0` | 当时现行的 discover-v4 / review-v2。 |
| 候选 A | `sijian-v2-evidence-tension-v1` | `evidence-tension-v1 / 1.0.0` | 更明确地表达证据和材料间的差异。 |
| 候选 B | `sijian-v2-concise-complete-v1` | `concise-complete-v1 / 1.1.0` | 精简重复，同时保留完整思考。 |

### 接入和操作

需准备带 `services/agent/evaluation_profiles.py`、对应提示词和真实服务入口的 Sijian checkout，以及可用的 Codex CLI 登录。启动 MyEval 前设置 `MYEVAL_SIJIAN_ROOT` 为该 checkout 的绝对路径；默认查找 `~/AiCoding/Sijian`。MyEval 不包含这份产品源码。

```mermaid
flowchart LR
    C[冻结文字与显式历史] --> P[产品白名单选择 profile]
    P --> S[独立 Sijian 服务]
    S --> D[真实 discover 或 review]
    D --> O[业务交付与引用]
    O --> E[独立配对评价]
```

1. 在“新建实验”选择思间和 `sijian-v2-development`，选全部 6 例；以上表基线对两个候选，重复 1 次，核对 **18 项运行**。这是开发试跑，不复现历史 72 项正式实验。
2. 运行后查看“配置与来源”：产品回显的 profile、提示词版本与哈希应对应冻结配置。适配器为每个 trial 启动独立服务并实际调用 `/discover` 或 `/review`，不用原生用户库，也不在评测侧重写业务提示词。
3. 对发现任务逐条核对联系引用；合理的空关系数组也可以完成任务。对复盘任务核对当前问题、历史说法和原文是否被混为一谈。
4. 使用 `sijian-v2` 量表做配对评价。对裁判声称的重大问题回到原文，保留分歧；不要只比较关系数量或平均分。
5. 同时读首次与当前成功情况、输入/输出/总 token、墙钟时间。稳定速度结论需要额外控制缓存、时段与重复，不从一次较短的回复推断。

实际来源、取消行为、任务限制和开发结果见[思间适配说明](../adapter-sijian.md)及[适配器源码](../../myeval/adapters/sijian.py)。此适配器的完整运行是一次文字业务调用；原生选材、保存和语音另行验收。

### 历史结果如何转成决定

| 2026-11-18/19 的观察 | 支持的决定与限制 |
| --- | --- |
| 正式设计为 12 家族、3 配置、各重复 2 次；72 项运行最终成功，其中一项首轮产品输出校验失败，经显式重试成功。 | 可以检查完整的同批比较，同时保留首次可靠性问题。不能把重试算成额外独立样本。[协议](../experiment-protocol-v2.md) · [验收](../acceptance/2026-11-18-platform-v2.md) |
| 结果交接记录：`concise-complete-v1 / 1.1.0` 在冻结目标上获两位独立 AI 裁判的正向区间，总 token 变化 **−3.27%**。 | 支持它作为有根据的改善候选；报告仍保留局部增义问题。没有据此宣称真人满意、问题已消失或稳定提速。[结果交接](../handoff/2026-11-18-v2.md#产品结果与保护) |
| 独立 Simulator 旅程完成虚构文字的复盘、引用回看、保存及重启后打开。 | 证明该文字路径和保存读回；不证明语音、真机或真实用户效果。 |

**2026-11-18/19 这一轮没有自动替换普通默认。** 当时思间保持 `baseline-v1` 与原有 discover-v4 / review-v2；历史 V13 基线保留。候选的后续采用应另行确认目标用户的真实价值和剩余忠实度问题。

迁移到自己的助手时，保留同一事实输入、对话历史和模型请求条件，仅改变产品注册的候选策略。加入“没有足够证据，应当不联系或不下结论”的材料，让克制与有用都能被评价。

## 案例二：pome，少用 token 是否仍能自然回应并忠实保存

### 问题与比较设计

pome 的候选尝试回应当轮交流需要、减少重复推动，以及压缩参考材料的输入开销。评测同时关心对话和最终日记：聊得自然不能抵消把助手建议写成儿童经历。

| 项目 | 本案例设置 |
| --- | --- |
| 项目 / 公开任务包 | `pome` / [`pome-v2-development`](../../taskpacks/pome-v2-development.json)，版本 `1.0.0`。 |
| 公开开发材料 | 8 个原创虚构情境家族，固定后续台词；非真实儿童记录，不是教师金标。 |
| 实验单位 | 一段多轮对话连同整理、保存是一个 episode/case；8 case × 3 配置 × 1 次 = **24 trial**。轮数或内部调用数不增加独立案例数。 |
| 相同请求参数 | `mode=isolated_full_run`，`model=deepseek-flash`；聊天 `chat_thinking=enabled`、`chat_reasoning_effort=low`；整理 `summary_thinking=disabled`，不发送整理 effort。 |
| 质量量表 | [`pome-v6`](../../rubrics/pome-v6.json)：回应需要、情绪共鸣、具体鼓励、交流价值、延伸、历史运用，以及对话和日记忠实度。 |

| 角色 | 配置 ID | 产品 profile / 版本 | 检验的改变 |
| --- | --- | --- | --- |
| 基线 | `pome-v6-current` | `reference-companion-v5 / 5.0.1` | V2 开始时的普通产品默认。 |
| 候选 A | `pome-v6-need-aware` | `need-aware-companion-v6 / 6.0.0` | 更关注纠正、拒绝、结束及已经完成的交流作用。 |
| 候选 B | `pome-v6-compact` | `compact-reference-v6 / 6.0.1` | 紧凑表达同一组参考，保留全部示范发言。 |

配置本身的 `version` 均为 `1`；表中的版本来自产品 profile。两者和实际内容哈希应分别读取，不能仅凭相同名称认定策略未变。

### 接入和操作

需准备具有真实 Handler、观测接口和 V6 profile 的 pomegranagent-v2 checkout。启动前用 `MYEVAL_POME_ROOT` 指向源码，用 `MYEVAL_POME_CREDENTIAL_DB` 指向已有授权的本机配置库。适配器只读必要的提供者配置，并在执行边界使用；不要把密钥写入任务包或提交配置库。旧 `integrations/` 补丁不是完整 V2 产品安装说明。

```mermaid
flowchart LR
    I[初始化虚构档案与独立数据库] --> U[本轮用户台词]
    U --> H[真实产品 chat]
    H --> T[该方案实际交付进入上下文]
    T --> U
    T --> S[真实 summary]
    S --> V[保存并重新读取状态]
    V --> E[分别评价对话和日记]
```

1. 选择 `pome-v2-development`，8 例、表中三个配置、重复 1 次，核对 **24 项运行**。配置明确选择 profile；不要依赖产品默认或适配器缺省来代替实验配置。
2. 打开一例的阶段与轨迹：真实调用应经过 `/api/state`、`/api/chat`、`/api/summary` 和保存读回。每个方案的下一轮必须接续**自己上一轮实际交付**，不能把某一方案的回复喂给所有方案。
3. 阅读完整 transcript 与整理结果，核对角色、纠正、结束意图、允许历史及日记来源。未交付候选不应进入上下文；保存后应只新增相应记录并移除草稿。
4. 用 `pome-v6` 量表评价。产品内部的理解、审校或修复阶段属于被测系统；只有另行配置的评分器才是独立 AI 评价。固定台词能控制输入，但不能证明真实儿童会如何接话。
5. 读全 episode 的实际 token 与耗时，保留失败调用和内部重试；无响应时用量可能未知。不要以提示词字符数或只看最后一轮代替真实总开销。

可进一步把固定 `input.child_turns` 替换为显式 `input.interaction_policy`，二者不可同时使用。已有规则分支和模型模拟用户接入；模拟器与产品用量分别记录，达到最大轮数也不自动表示目标完成。动态交互应另建实验，避免混进固定脚本分母。见[pome 适配说明](../adapter-pome.md#可选用户交互)、[交互契约](../../myeval/interactions/interactions-contract.md)与[源码](../../myeval/adapters/pome.py)。

### 历史结果如何转成决定

| 2026-11-18/19 的观察 | 支持的决定与限制 |
| --- | --- |
| 正式设计为 12 家族、3 配置、各重复 2 次；修正输入格式后 72 项运行完成。首次 `reviewedAt:null` 不符合产品接口，原失败保留。 | 执行契约需要实际验证；错误材料应形成显式修订版本，不能悄悄覆盖失败。[协议](../experiment-protocol-v2.md) · [验收](../acceptance/2026-11-18-platform-v2.md) |
| 结果交接记录：`compact-reference-v6 / 6.0.1` 总 token **−28.37%**，质量非劣尚未成立，没有提速结论。 | 这是开销方向的收益；不足以判定该候选整体胜出。语义复核还记录了角色替换问题，需与平均分一起处理。[结果交接](../handoff/2026-11-18-v2.md#产品结果与保护) · [语义复核记录](../acceptance/2026-11-18-platform-v2.md#最终整合复核) |
| 产品浏览器实际走过合成语音输入、ASR、chat、回复音频、整理、保存与刷新读回。 | 支持该链路能执行；输入是成人合成语音，人工听感未评，不是儿童语音识别率或声音质量验收。[适配说明](../adapter-pome.md) |

**2026-11-18/19 的 V2 评测未将新候选改为普通默认。** 当时所用基线 `reference-companion-v5 / 5.0.1` 是用户在 **2026-11-13 的另一轮决策**中采用的，不能把两次实验混成“从未切换默认”，也不能把那次采用当作 V6 候选已获批准。[此前落地记录](../handoff/2026-11-13-pome-new-c.md)

迁移到自己的对话 Agent 时，用“完整会话加最终产物”作为单位，记录每个方案真实形成的上下文。把交流质量、事实忠实、状态保存和开销分开设门槛；后续补充经授权的真实使用者材料与专家评价，才能判断压缩是否值得采用。

## 案例三：Sidelit，结构通过为什么仍可能淘汰候选

### 问题与比较设计

第一轮比较照片点评中的证据约束与显式摄影意图。第二轮进一步改变产品契约，尝试不强制输出审美分数，并比较单次生成与先观察后建议。两轮的任务和输出能力不同，应分别报告。

| 路线 | 公开开发任务包 | 材料与运行数 |
| --- | --- | --- |
| 原点评契约的显式兼容入口 | [`sidelit-v2-development-compat-20261118`](../../taskpacks/sidelit-v2-development-compat-20261118.json)，版本 `1.0.0`。 | coffee、chelsea、astronaut 三张已见公开许可照片；3 case × 3 配置 × 1 次 = **9 trial**，3 个图像家族。 |
| 无分数新契约 | [`sidelit-scorefree-development-v1`](../../taskpacks/sidelit-scorefree-development-v1.json)，版本 `1.0.0`。 | 同三张已见照片、12 条新编虚构用户请求；12 case × 3 配置 × 1 次 = **36 trial**，仍只有 **3 个图像家族**。 |

原点评兼容入口的配置：

| 角色 | 配置 ID | profile |
| --- | --- | --- |
| 基线 | `sidelit-author-schema-v1-compat-20261118` | `author-schema-v1` |
| 候选 A | `sidelit-evidence-grounded-v1-compat-20261118` | `evidence-grounded-v1` |
| 候选 B | `sidelit-intent-conditioned-v1-compat-20261118` | `intent-conditioned-v1` |

三者均显式使用 `protocol_version=sidelit-critique-eval-v1`、`build_id=legacy-compat-20261118`、`mode=fixed_context_rerun`。配置版本均为 `1.0.0`，业务 profile 版本分别为 `1.0.0 / 1.1.0 / 1.1.0`。历史 V1 固定同模型、448 长边、seed 42、temperature 0.1、最大输出 512 token；这些由产品运行时声明，不能给适配器随意追加解码参数。

无分数新契约的配置：

| 角色 | 配置 ID | profile / 版本 |
| --- | --- | --- |
| 作者对照 | `sidelit-scorefree-author-control-v1` | `author-schema-v1 / 1.0.0` |
| 单次候选 | `sidelit-scorefree-single-v1` | `score-free-observation-v1 / 1.1.0` |
| 两阶段候选 | `sidelit-scorefree-evidence-first-v1` | `score-free-evidence-first-v1 / 1.1.0` |

三者都使用 `protocol_version=sidelit-critique-eval-v2` 与 `fixed_context_rerun`；省略 `build_id` 时绑定该协议的 `scorefree-20261118` 构建。案例的 `product_request` 显式声明 purpose、意图和约束，`response_language=en`、`rating_request=null`；原始意图必须与对象中的文本一致。作者对照保留旧报告、忽略意图，不应把它评成“接到意图后不遵从”。

### 接入和操作

需准备 **Mac** 上兼容的 Sidelit 源码、Swift/C++ 原生构建、锁定模型权重和已声明来源的图片。启动前可用 `MYEVAL_SIDELIT_ROOT` 指向产品目录，`SIDELIT_CRITIQUE_MODEL_DIR` 指向权重目录；额外公开图片目录通过 `MYEVAL_SIDELIT_PUBLIC_MEDIA_ROOTS` 显式声明。默认图片在产品的 `POC/Resources/Samples`，MyEval 不下载照片、不读取私人相册，也不随仓库附带原图或模型。

```mermaid
flowchart LR
    I[许可、原图字节与意图] --> F[核对图片和构建哈希]
    F --> N[产品共享 Swift 与 C++ runtime]
    N --> O[完整最终交付]
    O --> J[原图与交付一起送评]
    J --> G[内容门槛和严重错误复核]
    G --> K[晋级新确认集或停止]
```

1. 先核对[构建兼容说明](../adapter-sidelit-compat.md)。原 `sidelit-v2-development` 仍保留历史语义，其旧默认构建与后来共享源码不一致时应被拒绝。运行 V1 时显式选择兼容任务包，不改写旧快照来绕过保护。
2. 从上面一条路线开始创建实验，先重复 1 次，核对 **9** 或 **36** 项运行。兼容入口曾完成来源预检和暂停建立，不能把该预检算作一次新模型推理；实际运行仍需自己的匹配环境。
3. 打开“原图与输入”，确认实际图片及哈希一致。适配器先保存不可变原图，再调用共享 native runtime；检查 native 终态与解析结构，同时保留原始失败。JSON 合法不能代替视觉事实核对。
4. V1 用 [`sidelit-v2`](../../rubrics/sidelit-v2.json)，新契约用 [`sidelit-scorefree-v1`](../../rubrics/sidelit-scorefree-v1.json) 量表。评分器必须实际收到原图；产品自己输出的分数是被评内容，不是外部裁判。
5. V1 重点核对物体、位置、技术因果与建议是否有图像依据。新契约还应检查是否偷偷评分、是否符合用户约束、观察是否有用；合法弃答要保留覆盖损失。基线不能接收的意图属于能力差异，应单列。
6. 看完整调用开销。两阶段候选要累计两次 native 调用，阶段不算独立样本；每次 attempt 启动新进程，固定 seed 重复和文件缓存也不能证明暖模型吞吐、磁盘冷启动或真机能耗。

详细接口见[原生适配器](../adapter-sidelit.md)、[无分数协议](../adapter-sidelit-scorefree.md)和[源码](../../myeval/adapters/sidelit.py)。

### 历史结果如何转成决定

| 历史轮次 | 观察 | 决定与限制 |
| --- | --- | --- |
| 2026-11-18 第一轮正式比较 | 8 个图片来源 × 2 意图 × 3 配置 × 2 重复，共 **96 trial** 完成。公开结果交接仅支持技术依据的局部正向，语义复核保留错误裁切断言。 | 不宣称总体质量胜出；2 种意图仍按一张原图计家族。[协议](../experiment-protocol-v2.md) · [验收](../acceptance/2026-11-18-platform-v2.md) · [结果交接](../handoff/2026-11-18-v2.md#产品结果与保护) |
| 2026-11-18 无分数开发轮 | 三配置均结构交付 **12/12**；单次候选有用且有据观察 **3/12**、严重错误 **4/12**；两阶段候选分别 **9/12**、**3/12**。 | 两候选均未达到预先 **10/12 有效观察且无新增严重虚构**的门槛，均不晋级；新确认集保持封存。[详细结果与限制](../adapter-sidelit-scorefree.md#2026-11-18-实际开发结果) |
| 无分数开发的执行开销 | 作者对照、单次、两阶段中位耗时分别为 **5.65 / 7.29 / 10.10 秒**。 | 同一 Mac 开发运行的描述；三图已见，内部 AI 判断也不是摄影师评价或泛化证明。更多阶段没有自动换来合格内容。[开发结果](../adapter-sidelit-scorefree.md#2026-11-18-实际开发结果) |

**保留原默认，停止晋级是本案例的有效结果。** 新契约的工程能力已经走通，但内容没有过门槛，不能为获得正结果而继续在同一批材料上调参并称作留出验证。新 CLI 也不等于原生 App 已接入无分数流程。

另行执行的 Simulator Vision 回放验证了图像回放、丢失与恢复等路径，实际拍照为 0；Mac 视觉模型推理、Simulator 规则回放、iPhone 推理及物理相机是不同证据，后两项没有由本轮证明。[原生旅程记录](../acceptance/2026-11-18-platform-v2.md#已完成的主脑旅程)

迁移到自己的视觉 Agent 时，按原始图片划分材料，固定实际图片字节，明确用户意图由哪些方案接收。将结构、事实、实用性和严重错误设为不同门槛；候选改变输出契约或增加阶段时，记录为整体能力改变，避免把全部收益归因为视觉理解更强。

## 把这套方法用于自己的 Agent

从[演示适配器](../../myeval/adapters/demo.py)和[适配契约](../adapter-contract.md)开始：`describe(configuration)` 声明来源与能力，`run(case, configuration, ctx)` 调用真实业务入口并带回交付、事件、已知用量和未知项。新增任务包记录 case、family、来源、方案和清晰的预期行为。

第一轮只需一个强基线、少量各有假设的候选和有边界差异的材料。先证明真实调用与保存，再做开发筛选；冻结后用新材料判断质量与成本，最后补充目标用户和实际设备的证据。完整按钮操作见[图文指南](../walkthrough.md)，可直接使用与需另建能力的范围见[能力说明](../capabilities.md)，自动化入口见 [HTTP/CLI](../api-v2.md)。
