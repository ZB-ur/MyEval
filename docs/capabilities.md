# MyEval 能评什么

MyEval 适合回答一个具体问题：**同一组材料交给当前方案和候选方案，交付质量、执行可靠性与开销分别怎样变化？** 它将运行、评价和作出选择所依据的证据放在同一个本机工作台中。

本页对应 2026-11-25 集成版本。[图文操作指南](walkthrough.md)可以直接用无模型演示体验完整流程；[三个实际项目的案例](playbooks/real-projects.md)展示真实接入和不同结论。[本版验收](acceptance/2026-11-25-release.md)与[三项目历史验收](acceptance/2026-11-18-platform-v2.md)分别说明平台运行和业务实验的证据。

## 直接可用：组织比较、阅读证据、保存判断

以下是仓库自带的平台能力。执行真实 Agent 或调用评分模型时，还需准备下一节列出的环境。

| 你想做的事 | 现在可以怎样做 | 结果应怎样理解 |
| --- | --- | --- |
| 一次比较多个方案 | 每个实验选择 1 个基线和 1–15 个候选；同案例、同重复序号分别配对。 | 批次可以组织多个实验；不同项目不会被平均成一个总分。 |
| 固定实验条件 | 冻结任务包或数据集版本、配置、来源哈希；执行前再次核对源码。来源改变时将该项记为失败，并阻止它发送产品请求。 | 冻结能发现漂移；它不会自动检出旧版本或重建完整产品环境。源码快照可能为部分归档。 |
| 重复执行并检查失败 | 保存每项运行及历次尝试，查看阶段、输出和错误；显式重试追加记录。 | 失败、超时、取消、中断、拒绝和不支持都保留。当前成功率与首次成功率应分开读。 |
| 检查客观约束 | 适配器可记录引用是否存在、JSON 是否有效、文件是否保存、状态是否读回等规则结果。 | 规则通过只证明被检查的条件；语义是否忠实、建议是否有价值还需评价。 |
| 邀请匿名评阅 | 创建独立席位，随机安排 A/B，保存偏好、理由、平局或无法判断；支持匿名导出。 | 管理员可见配置身份。真人评价与“验收试填”分别计数；试填不能充当用户意见。 |
| 管理开发材料和留出材料 | 导入不可变数据集版本，记录来源、家族、划分和已暴露材料；同一家族不能同时属于开发与留出。 | 划分约束帮助防止混算；材料是否具有代表性、是否真正未被作者见过，仍需实验负责人保证。 |
| 导入旧运行、重新阅读 | 导入既有终态、尝试、媒体及历史评价归档；保留原始身份、失败与缺失。 | 导入不会重放产品，也不会把旧评分自动变成新实验的当前评分。 |
| 记录是否采用候选 | 保存通过、失败或证据不足的质量判定，绑定当时的输出和评价；证据更新后标记旧判定。 | 执行成功但没有质量依据不能通过。判定记录不会自动切换产品默认或部署版本。 |
| 控制本机任务 | 暂停新调度、取消执行或评分，设置重复、并发、时限及观测用量预算。 | 暂停时在途任务继续；取消本机进程不证明远端计算或计费已停止。预算不是绝对账单上限。 |
| 看开销与未知项 | 分开显示请求参数、实际回报值、耗时、可观察 token 与缺失用量。 | 未知不是 0；未确认的模型与推理强度不会照抄请求值。少用 token 不自动证明质量、速度或费用更好。 |
| 搬运与恢复证据 | 导出 JSON/JSONL、ZIP、逐次证据及媒体；对 SQLite 和白名单附件备份，校验后恢复到独立空目录。 | 管理员导出含配置身份和业务内容。备份不包含模型权重、产品依赖、提供者凭据和历史手册视频，恢复后另建管理员令牌。 |

## 需要适配器或外部环境：真实执行与独立评价

| 场景 | 已有能力与实测路径 | 使用前还需准备 |
| --- | --- | --- |
| 提示词、模型参数和策略比较 | 产品通过 HTTP、CLI 或共享业务模块运行；随仓库提供 Sijian、pome、Sidelit 适配器及开发任务包。 | 对应产品源码、兼容接口与实际模型环境。仓库不附带三个产品，旧集成补丁也不是完整安装包。自有 Agent 需实现[适配契约](adapter-contract.md)。 |
| 独立 AI 评分 | 独立持久队列；按量表逐项或成对评价；可精确指定历史 attempt 重评，不再次调用产品。保存版本、引文、失败和分歧。 | 已登录、支持所需参数的 Codex CLI 与可用模型额度。评分会产生额外调用；评分器只读取允许材料，不获执行工具权限。见[评分契约](evaluation-v2.md)。 |
| 动态多轮对话 | 固定脚本、依回复分支的规则用户、模型模拟用户；pome 已真实交替调用产品并整理、保存。 | 适配器需把实际交付接回下一轮。模型用户要单独配置和计费；模拟用户可能补造事实，不能代替真人行为分布。见[交互与状态](interactions-v2.md)。 |
| 图片理解与建议 | 原图字节及哈希随 attempt 保存；评分模型实际接收图片。Sidelit 已通过产品共享运行时在 Mac 推理。 | 图片来源、许可或明确授权、原始文件、兼容模型与构建。不能仅凭路径或文字描述声称已做视觉评价。 |
| 跨轮状态与最终产物 | 文件工作区支持快照、重置、再次打开、产物哈希和内容核验；pome 另有独立数据库保存读回。 | 产品适配器负责数据库、浏览器和外部服务的隔离与重置；通用文件组件不自动接管这些状态。 |
| 原生界面和语音流程复核 | 历史上实际操作过 Sijian Simulator 文字复盘、pome 合成语音的 ASR/对话/回复音频/保存，以及 Sidelit Simulator Vision 回放。 | 需另行准备应用、模拟器、录屏和人工复核。它们是独立产品旅程证据，当前任务执行器不会自动完成任意原生界面或音频旅程。 |

## 尚未直接提供的典型场景

这些场景可以成为后续适配方向，但当前开箱能力不能覆盖其完整闭环。

| 你可能需要的场景 | 当前缺少的部分 |
| --- | --- |
| 任意网站、原生 App 或带副作用的多 Agent 工具环境 | 通用界面操作循环、容器与网络编排、统一世界状态和副作用隔离。独立本机目录不等于完整沙箱。 |
| 专项 RAG 与系统性安全评测 | 检索金标、检索到回答的专项度量，以及自动攻击生成、注入/越权/泄漏红队覆盖。可以自行定义案例和规则，但没有现成专项套件。 |
| 实时语音、物理设备与长期用户效果 | 流式时延、真人听感、真实儿童/专家反馈、iPhone 模型推理、相机快门、热与能耗，以及长期行为收益。 |
| 专家标注运营与评分器有效性 | 专家金标集、持续一致性和漂移监测、团队标注分派。内部合成锚点只能检查与规范的一致，不能证明裁判代表真实用户。 |
| 生产流量与团队级服务 | 在线 A/B、生产持续采样、灰度回滚、已接通的 CI 阻断、企业 SSO/RBAC、多租户、分布式执行和生产 SLA。现有 CLI 判定退出码可供后续 CI 集成。 |

## 看清一次运行和一个独立样本

四个名称回答不同问题：

| 名称 | 表示什么 | 例子 |
| --- | --- | --- |
| case（案例） | 一份确定输入与任务 | 同一张照片加一条摄影意图。 |
| trial（运行项） | 案例 × 配置 × 重复序号 | 3 个方案各跑 2 次，产生 6 项运行。 |
| attempt（尝试） | 某项运行的一次实际执行尝试 | 一项运行失败后重试，变成 2 次尝试，仍只有 1 项运行。 |
| family（家族） | 应共同计权的原始情境或来源 | 同一照片的 2 种意图、重复执行和多个裁判，都不增加独立照片数。 |

比较先合并同案例的重复，再合并家族内变式，最后按家族等权。一起查看有效家族、配对覆盖、缺失、分歧和区间；样本少、区间跨零或裁判方向不同，就保留不确定性。评分引文存在也只证明“引用可定位”，不能自动证明裁判对语义或图片的解释正确。

## 从哪些证据得出哪些结论

| 证据层次 | 可以回答 | 单独不能回答 |
| --- | --- | --- |
| 平台执行与规则 | 请求是否执行、结构是否有效、引用是否存在、结果是否保存、失败是否保留。 | 候选是否更有帮助。 |
| 业务质量评价 | 在本次材料和量表下，独立 AI 或评审者怎样判断真实交付；哪里改善，哪里退化。 | 未采集的真实用户体验、长期效果或设备表现。 |
| 实际用户与设备 | 经授权的用户反馈、专家判断、真实设备测量或明确的产品旅程。 | 未测人群、场景或设备的普遍收益。 |

因此，一轮好的评测既可以支持采用候选，也可以支持保留基线，或得出“证据不足，需要新材料”的结论。三种结果都应保留依据，见[实际项目 playbook](playbooks/real-projects.md)。接口与扩展细节见 [HTTP/CLI](api-v2.md)、[架构](architecture-v2.md)和[实验协议](experiment-protocol-v2.md)。
